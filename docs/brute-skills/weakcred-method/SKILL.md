# 弱口令检测方法

## 1. 登录面侦察(先于一切尝试)
- 错误次数策略:同一账号故意错 N 次(N=3,5,10 阶梯),观察响应差异
  (锁死提示?验证码强制?)→ 摸清目标锁定策略,作为战术情报入账
- 验证码:次数阈值前是否免验证码;识别升级后换面/换源继续
- 响应差异:错误密码 vs 错误账号的报文差异(可枚举用户名?)
- 协议:query_intel 优先(上游可能已还原加密协议);否则抓登录 JS 自行还原

## 1b. 限流四态分类(下结论前必须分类,禁止只看 429)
无 429 ≠ 无限流——只查 429/锁定提示的判定法假阴性率高。发一波 ~50 请求,
观察完整响应(状态码/响应体/头/延迟/下游成功与否)后归入四态:

| 态 | 信号 | 爆破还可打? |
|---|---|---|
| **硬账号锁死** | N 次失败后账号禁用,正确凭据也登不进 | 否(但锁死本身可报 DoS) |
| **软 IP 节流** | 仅对源 IP 出 429/延迟递增 | 可——换头(X-Forwarded-For 族)/换源绕 |
| **验证码注入** | 200 但 N 次后响应体切验证码 | 视情况——查校验端点是否服务端强制, API 路径是否跳过 |
| **影子静默限流** | 全程 200/401, 但请求被暗丢——真口令也开始登不进/响应变罐头 | **陷阱态**。裸循环看到"全 200 无 429"会误报"无限流" |

影子限流检测器:在已知位置埋真值, 负载下确认它仍有效:
```bash
# 种子: 爆破集第 500 位放自己测试账号的真 OTP
# 循环跑到 500 时若正确码不再通过 → 端点在静默丢弃, 不是无防护
KNOWN_GOOD="123456"   # 自己测试账号的当前真 OTP
for n in $(seq 0 600); do
  CODE=$([ "$n" = "500" ] && echo "$KNOWN_GOOD" || printf "%06d" "$n")
  curl -s -o /dev/null -w "%{http_code} " -d "code=$CODE" http://target/otp-verify
done
# 末尾观察第 500 发是否仍 200——是=无影流, 否=影子限流(换源/换面)
```

## 2. 目标选择(优先级)
1. 默认/出厂口令(厂商名+123/年份组合)——命中率最高
2. 模式口令:账号名+后缀(123456/@123/666/888/QQ);学号工号体系直接试
3. top500 弱口令,进而语义组合全开

## 4. 证据与落账
- 拿到成功立即停止对该账号的重复尝试(已验证,继续打是浪费火力和时间)
- 证据:登录成功响应片段(用户名回显/session cookie 截断)
- 落账:report_vulnerability(核心系统可登录=高危;PII 系统=critical 候选)
  + publish_intel(凭据给 nday/api 下游,注明仅限授权测试)
