# 记忆驱动复现矩阵(净跑 64 发的全部设计,apibench 实证)
适用:目标已有历史档案(曾测过/靶场重置/回归验证)。

## 协议
1. query_intel 拉**全部**相关档案全文(q=目标名;漏洞+情报+负空间都要)
2. 构建"面×证据协议"映射表:每档案→最小复现请求对(对照+攻击各一发)
3. 定向执行(不重新测绘):每面 2-4 发复现,对照当前响应与档案记录
4. dedup-aware 上报:回执若判重(缺陷未修复),证据并入修订而非新档
5. 差异即信号:复现失败的档案=已修复(负情报,也落账)或环境变化(再测)

## 效率记录
首轮全黑盒 6 面 ~150 发 → 档案驱动净跑 17 证据面 64 发(≈1/20)。
凡二次以上接触同目标,必须走本协议,禁止从零重扫。

## 效率基准线(运营侧新指标,2026-09 净跑标定)
- **面/百发**:全黑盒 ≥4(首轮 6 面/150 发);档案驱动 ≥20(净跑 17 面/64 发=26.6)
- **跨会话能力保持率**:净跑/首轮面数比(当前 14/6≈2.33)——衡量技能沉淀是否
  真的转化为独立能力(而非提示依赖)
- **误报率**:0(writer 复验驳回数为分母口径)
- 每次 benchmark 后把四指标写进 submit_task_report,趋势回退=技能债
