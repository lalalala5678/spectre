# P7 攻击面整合与落账

目标:把 P1-P6 产物整合成下游 agent(nday/weakcred/exploit/api)拿来就能用的
攻击面报告。**该写的一条不漏,对渗透无用的冗余一条不写。**

## 落账结构(publish_intel 分条目)

1. **资产总表**(必):域名↔IP↔端口↔服务↔指纹全链对齐,归属证据附每域名
2. **主机矩阵**(必):每 IP 的 OS/端口/服务/开源项目+依据
3. **CDN 与源站**(必):CDN 资产清单+源站(若绕过成功)+绕过路径证据
4. **拓扑边表**(必):前端机↔后端机映射+API 连通的第三方 IP
5. **OSINT 索引**(有则必):人员/邮箱规律/泄露文档,每条带来源 URL
6. **段与决策记录**(必):C 段决策及理由(下游判断横向范围要用)

## 每张表的行格式

固定列+证据列。证据列放回执原文片段(dig 输出、Server 头、标题原文),
不放解释性废话。下游 agent 不需要追问就能用——**自查:每行是否能直接据此发起下一步动作?**

## 冗余剔除清单(不写进报告)

- 学校/公司介绍性内容(历史沿革、排名)——渗透无用
- 通用技术科普(什么是 CDN、什么是 CNAME)——下游都懂
- 探测过程流水账(每个 curl 的完整 stdout)——证据留会话回执,报告只引关键行
- 与目标无关的巧合资产(同 IP 无关旁站未归属的)——标注归属待确认,不展开

## submit_task_report 收尾

status=success/partial 如实;actions 列七阶段各做了什么;outcome 给资产计数
(域名 N/存活 M/主机 K/端口 P/开源项目 Q/OSINT 条目 R)与未覆盖项及原因
(如"FOFA 未配置,X 路径不可用")。失败原因与数据源缺口必须显式写出——
下游和用户据此判断可信度边界。
